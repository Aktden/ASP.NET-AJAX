## Описание

**Big Data Utility** - графическое приложение на Python с интерфейсом на PySide6, предназначенное для быстрого исследовательского анализа данных (EDA). Основная идея: загрузил файл - выбрал нужные графики - получил полноценный HTML-отчёт в браузере.

Приложение подходит для аналитиков и разработчиков, которым нужно быстро посмотреть на структуру данных, распределения, корреляции и выбросы без написания кода вручную.

Интерфейс выполнен в тёмной теме, вдохновлённой дизайном Telegram Desktop.



## Возможности

- **Загрузка файлов** CSV и Excel (`.xlsx`, `.xls`) через диалог выбора файла
- **Автоматическая оптимизация памяти** при загрузке - downcast числовых типов и конвертация строковых столбцов с низкой кардинальностью в `category`
- **Динамическая проверка доступности** каждого типа графика сразу после загрузки файла - рядом с каждым чекбоксом появляется цветная подсказка с объяснением, почему визуализация недоступна
- **Фильтрация строк** перед анализом по произвольному условию (столбец + оператор + значение)
- **15 типов визуализаций** - от гистограмм до 3D-рассеивания и радарных диаграмм
- **Опция «Все графики»** - одним чекбоксом включить все доступные для данных типы
- **Фоновый поток анализа** - интерфейс не зависает при обработке больших файлов
- **Прогресс-бар и строка статуса** с отображением текущего шага
- **Цветной лог выполнения** с временными метками: белый - информация, зелёный - успех, жёлтый - предупреждение, красный - ошибка
- **HTML-отчёт** с интерактивными графиками Plotly, открывается в браузере автоматически
- **Сохранение отчёта** в произвольное место на диске
- **Тёмная тема** в стиле Telegram без зависимости от локального фонового изображения



## Типы визуализаций

### Основные визуализации

| Тип | Описание | Требования к данным |
|---|---|---|
| **Информация о данных** | Таблица с типами столбцов, количеством пропусков, уникальных значений и базовой статистикой | Любые данные |
| **Гистограммы** | Распределение значений для первых 3 числовых столбцов | ≥ 1 числовой столбец |
| **Диаграммы размаха (Boxplot)** | Медиана, квартили и выбросы для первых 3 числовых столбцов | ≥ 1 числовой столбец |
| **Диаграммы рассеивания** | Scatter plot между двумя первыми числовыми столбцами | ≥ 2 числовых столбца |

| Тип | Описание | Требования к данным |
|---|---|---|
| **Матрица корреляций** | Heatmap с коэффициентами Пирсона, цветовая шкала RdBu от −1 до +1 | ≥ 2 числовых столбца |
| **Линейные графики** | График первого числового столбца по индексу строк | ≥ 1 числовой столбец |
| **Все графики** | Активирует все доступные для данных типы разом | Зависит от данных |

| Тип | Описание | Требования к данным |
|---|---|---|

## Использование

### Шаг 1 - Загрузить файл

Нажмите кнопку **«Выбрать файл»**. Откроется системный диалог, в котором можно выбрать:
- CSV-файл (`.csv`) - кодировка UTF-8, разделитель определяется автоматически
- Excel-файл (`.xlsx` или `.xls`)

После выбора файла приложение автоматически загружает данные и обновляет статусы всех чекбоксов — напротив каждого типа визуализации появится подсказка, доступен он или нет, и по какой причине.

Чтобы сбросить выбор, нажмите кнопку **«×»** рядом с именем файла.

### Шаг 2 - Настроить фильтр (опционально)

В секции **«Фильтрация данных»** можно ограничить анализируемые строки:

1. Выберите столбец из выпадающего списка
2. Выберите оператор сравнения
3. Введите значение

Если поле значения оставить пустым, фильтр применяться не будет — в анализ попадут все строки.

### Шаг 3 - Выбрать типы визуализаций

Отметьте чекбоксы в трёх группах:
- **Основные визуализации** - базовые типы для первого знакомства с данными
- **Статистические графики** - корреляции и тренды
- **Дополнительные визуализации** - более специализированные виды

Если нужно сразу всё, отметьте **«Все графики»** - приложение само включит все типы, применимые к текущему файлу.

> Чекбоксы, неприменимые к текущим данным (например, 3D-график при отсутствии трёх числовых столбцов), отображаются с красной подсказкой и заблокированы для выбора.

### Шаг 4 - Сгенерировать отчёт

Нажмите **«Сгенерировать отчёт»**. В строке статуса и прогресс-баре отображается ход выполнения:

```
Загрузка данных...      10%
Обработка данных...     30%
Генерация отчёта...     80%
Готово                 100%
```

После завершения HTML-файл откроется в браузере автоматически.

### Шаг 5 - Сохранить отчёт

По умолчанию отчёт сохраняется во временный файл системы. Чтобы сохранить его постоянно, нажмите **«Сохранить отчёт»** - откроется диалог с именем файла вида `data_report_20240101_120000.html`.



## Фильтрация данных

Виджет фильтрации позволяет передать в анализатор только нужное подмножество строк. Условие формируется как pandas-запрос и применяется через `DataFrame.query()`.

Поддерживаемые операторы:

| Метка в UI | Pandas-оператор | Пример условия |
|---|---|---|
| Равно | `==` | `city == "Москва"` |
| Не равно | `!=` | `status != "closed"` |
| Больше | `>` | `age > "30"` |
| Меньше | `<` | `price < "1000"` |
| Больше или равно | `>=` | `score >= "90"` |
| Меньше или равно | `<=` | `rating <= "3"` |
| Содержит | `str.contains` | `name.str.contains("Иван", case=False)` |

> Значение всегда передаётся как строка - pandas приводит тип автоматически при вычислении запроса.



## HTML-отчёт

Отчёт представляет собой самодостаточный HTML-файл. Он содержит:

- **Заголовок** с датой и временем генерации, путём к исходному файлу, количеством строк и столбцов, использованием памяти
- **Блоки с графиками** - каждый в отдельном `div` с заголовком и интерактивным виджетом Plotly
- Подключение Plotly через CDN (`https://cdn.plot.ly/plotly-latest.min.js`)

Все графики Plotly интерактивны: можно приближать, отдалять, скрывать серии по клику на легенду, наводить для просмотра значений, скачивать как PNG через встроенную кнопку Plotly.



## Оптимизация памяти

После загрузки данных автоматически выполняется метод `optimize_memory()`, который:

1. **Целочисленные столбцы** - понижает тип до наименьшего подходящего (`int8` → `int16` → `int32` → `int64`) на основе минимального и максимального значения в столбце
2. **Вещественные столбцы** - применяет `pd.to_numeric(..., downcast='float')` для перехода к `float32`, где это возможно
3. **Строковые столбцы** - если доля уникальных значений менее 50% от длины датафрейма, конвертирует столбец в тип `category`

Это позволяет работать с файлами, которые при наивной загрузке занимали бы в 2–4 раза больше оперативной памяти.



## Описание модулей

### `main.py`

Точка входа. Создаёт `QApplication`, применяет стиль `Fusion`, инстанцирует `VisualizerWindow` и запускает главный цикл событий Qt.

### `window.py` - `VisualizerWindow`

Главное окно приложения. Отвечает за:
- Компоновку всех виджетов (заголовок, панель выбора файла, фильтр, три группы чекбоксов, кнопки, лог, прогресс-бар, строка статуса)
- Обработку событий пользователя: выбор файла, сброс файла, запуск анализа, сохранение отчёта
- Обновление статусов чекбоксов сразу после загрузки файла через `update_checkbox_statuses()`
- Приём сигналов от `AnalysisThread` и отображение прогресса или ошибок в логе
- Фоновое изображение окна, которое масштабируется при изменении размера через `resizeEvent()`

### `visualizer.py` - `UnifiedBrowserVisualizer`

Ядро приложения. Отвечает за:
- Загрузку CSV-файлов (с попыткой автоматического определения заголовков) и Excel-файлов
- Оптимизацию памяти загруженных данных
- Автоматическое обнаружение столбцов с датами через `pd.to_datetime()` с `errors='coerce'`
- Построение каждого типа графика в виде объекта `plotly.Figure` и добавление его в список `self.figures`
- Сборку итогового HTML-файла с шапкой и всеми графиками, сохранение во временный файл и открытие через `webbrowser.open()`

### `analysis_thread.py` - `AnalysisThread`

Наследник `QThread`. Запускает весь pipeline анализа в отдельном потоке, чтобы не блокировать UI. Принимает путь к файлу, словарь опций и опциональное условие фильтрации. Испускает четыре сигнала:

| Сигнал | Тип данных | Назначение |
|---|---|---|
| `update_progress` | `int` | Процент выполнения (0–100) для прогресс-бара |
| `update_status` | `str` | Текст для строки статуса |
| `analysis_complete` | `object` | Путь к готовому HTML-файлу |
| `error_occurred` | `str` | Текст исключения при ошибке |

### `widgets.py`

Содержит два переиспользуемых виджета.

**`EnhancedFilterWidget`** - горизонтальная панель фильтрации:
- `QComboBox` для выбора столбца (заполняется динамически после загрузки файла)
- `QComboBox` для выбора оператора из списка: `==`, `!=`, `>`, `<`, `>=`, `<=`, `str.contains`
- `QLineEdit` для ввода значения с плейсхолдером
- Метод `get_filter_condition()` возвращает строку pandas-запроса или `None`, если значение не введено

**`CheckBoxWithStatus`** - чекбокс с подписью-статусом:
- `QCheckBox` с текстом опции
- `QLabel` с подсказкой о доступности (серый / зелёный / красный / синий)
- Метод `set_status(text, color)` для обновления подписи из кода

### `styles.py` - `TelegramStyle`

Класс с палитрой цветов (`COLORS`) и статическим методом `apply(widget)`, который применяет единый QSS-стиль ко всему дереву виджетов. Включает стили для `QWidget`, `QMainWindow`, `QPushButton` (включая hover и pressed), `QLabel`, `QTextEdit`, `QCheckBox` (включая состояния checked/unchecked/hover), `QGroupBox`, `QScrollArea`, `QScrollBar`, `QStatusBar`, `QProgressBar`.

Цветовая палитра:

| Ключ | Значение | Использование |
|---|---|---|
| `background` | `#18222d` | Основной фон |
| `primary` | `#2b5278` | Рамки, кнопки |
| `secondary` | `#17212b` | Вторичный фон (лог, поля ввода) |
| `text` | `#ffffff` | Основной текст |
| `text_secondary` | `#8f98a0` | Подсказки, вторичный текст |
| `accent` | `#5288c1` | Прогресс-бар, выделения |
| `success` | `#5dc252` | Сообщения об успехе |
| `error` | `#eb5545` | Ошибки, отмеченные чекбоксы |
| `warning` | `#f0a732` | Предупреждения |



## Известные ограничения

- Гистограммы, боксплоты строятся только для **первых 3 столбцов** нужного типа, scatter matrix — для первых **4 столбцов**. При необходимости это ограничение можно изменить в `process_data()` в `visualizer.py`.
- Violin-диаграмма отображает не более **10 категорий** из выбранного столбца.
- Круговая диаграмма показывает **топ-10 категорий**, остальные объединяются в «Другие».
- Чекбоксы визуализаций активируются только после выбора файла; неподдерживаемые типы графиков остаются отключёнными с пояснением причины.
- Для просмотра отчёта в браузере требуется **подключение к интернету** — Plotly подгружается через CDN.
- Временные столбцы определяются эвристически через `pd.to_datetime()` без строгой проверки формата, что может давать ложноположительные результаты на некоторых данных.
- При возникновении ошибки в конкретной визуализации соответствующий график просто пропускается (ошибка выводится в консоль), а остальные строятся штатно.

## ETag API

В приложении есть локальный HTTP API для последнего сгенерированного HTML-отчёта. Он нужен для демонстрации ETag и проверки условных HTTP-запросов через `curl`. Сервер использует только стандартную библиотеку Python и слушает `127.0.0.1:8765`.

### Запуск

Запустите приложение обычным способом из каталога `DataVisual`:

```bash
python main.py
```

После запуска в журнале приложения появится адрес API. Сначала загрузите CSV/Excel и сгенерируйте HTML-отчёт. После этого ресурс будет доступен по адресу `http://127.0.0.1:8765/api/report`. До генерации отчёта сервер вернёт `404`.

### Проверка через curl

Все команды выполняются в Windows PowerShell, пока приложение запущено и HTML-отчёт уже сгенерирован. Используйте `curl.exe`, а не псевдоним PowerShell `curl`. В примерах замените `<etag>` на значение из заголовка `ETag`, сохраняя кавычки.

**1. Получить отчёт и ETag:**

```powershell
curl.exe -i http://127.0.0.1:8765/api/report
```

Ожидается `200 OK` и заголовок вида `ETag: "<sha256-хеш>"`.

**2. Проверить условный GET:**

```powershell
curl.exe -i -H 'If-None-Match: "<etag>"' http://127.0.0.1:8765/api/report
```

Если отчёт не изменился, сервер вернёт `304 Not Modified` без тела ответа.

**3. Проверить обязательность If-Match:**

```powershell
curl.exe -i -X PUT -H 'Content-Type: text/html' --data-binary '<h1>Новая версия</h1>' http://127.0.0.1:8765/api/report
```

Ожидаемый ответ: `428 Precondition Required`. Содержимое не изменится.

**4. Проверить сценарий двух клиентов:**

Сначала клиент A отправляет PUT с ETag, полученным на шаге 1:

```powershell
curl.exe -i -X PUT -H 'Content-Type: text/html' -H 'If-Match: "<etag-v1>"' --data-binary '<h1>Правка клиента A</h1>' http://127.0.0.1:8765/api/report
```

Сервер вернёт `200 OK` и новый ETag. Теперь клиент B отправляет запрос со старым `etag-v1`:

```powershell
curl.exe -i -X PUT -H 'Content-Type: text/html' -H 'If-Match: "<etag-v1>"' --data-binary '<h1>Правка клиента B</h1>' http://127.0.0.1:8765/api/report
```

Ожидаемый ответ: `412 Precondition Failed`. Изменение клиента A останется в отчёте.

**Важно:** успешный `PUT` изменяет текущий HTML-отчёт. Скрипт автоматической проверки ниже предварительно сохраняет исходный отчёт и восстанавливает его после тестов.
